08 · 除錯:這一層的東西壞掉時不會拋例外

前面七篇各自撞到一個問題,而那七個問題的形狀是同一個。

把它們並排看,這個 repo 的骨幹就出來了:Kit 這一層的東西壞掉時,多半不是拋例外,是安靜地回一個合法的值。 於是「呼叫成功了」變成一個沒有資訊量的訊號,而排查會從錯誤的地方開始。

驗證狀態:§3 的 log 機制引用官方逐字。§2 的對照表是前七篇的收攏,每一列的出處都標了篇章,證據等級以該篇為準。本 repo 沒有 Kit 環境,§4、§5 的做法未實機驗證。

1. 為什麼是這個形狀

Kit 是一個由幾百個 extension 組成、資料分散在兩份儲存、算圖與求值掛在不同迴圈上的框架(01)。這種架構下,大部分「失敗」在各自的元件看來都不是失敗:

  • 相依解不到 → 那個 extension 沒起來,而呼叫端拿到的是一個成功的回傳
  • 設定沒被採用 → 那個鍵仍然在設定樹上,讀得到
  • Fabric 沒有值 → 從 USD 讀得到一個合法座標
  • 圖沒被求值 → 物理照樣前進,時間戳一直在動
  • 貼圖檔不在 → 取樣回 (0,0,0),那是一個合法的顏色

每一個元件都做了它該做的事。錯的是我們拿來當證據的那個訊號,它回答的不是我們想問的問題。

2. 假訊號與真訊號

出處 看起來像證據,其實不是 真正該看的
02 extension 啟用回傳成功 節點型別、API 這類能力在不在
03 設定讀得到那個鍵 設成極端值,行為有沒有跟著變
04 座標讀得到一個數字 你讀的是 USD 那份還是 Fabric 那份
05 物理時間在前進 節點被算了幾次,跨幀比對有沒有增加
06 串流連線建立起來了 影格有沒有連續送出,不是只有第一張
07 影片檔的參數完全正常 貼圖路徑、log、貼圖平均色

右欄的共同點:它們都問「能力在不在」或「行為有沒有變」,而不是「這次呼叫有沒有成功」。

找新的驗收訊號時可以照這個模式推:先問「如果這件事其實壞了,哪個數字會不一樣?」——答得出來的才是可用的訊號。

3. log:在哪、怎麼調大聲

log 是這一層唯一會說實話的地方,而它預設不夠大聲。

檔案在哪。 官方說明:

"The path to the log file is written to stdout among the first lines when Kit starts."

啟動時的前幾行就印出來了。執行期要拿的話,路徑在設定 /log/file,或用 ${logs} token。

怎麼調大聲。 兩個旗標:-v 開 info、-vv 開 verbose。全域等級可以是 verbose、info、warn、error、fatal,預設是 info 寫入檔案。

只調某一部分。 可以針對特定 channel 設定,而且支援 * 與 ? 萬用字元,值除了上面五個等級之外還有 disable。這一點在排查時比全開 verbose 有用得多——全開之後真正要找的那行會被淹掉。

用法上的判斷:先確認要查的是哪個子系統,只把那一組 channel 調成 verbose,其餘維持或關掉。

4. 列舉查詢的正對照

§2 右欄的做法幾乎都會落到某種列舉或狀態查詢上,而列舉查詢有一個結構性的陷阱:

一個回空的查詢,同時相容於「東西不在」與「我的查法有洞」兩個世界。

查法寫錯——型別猜錯、屬性名拼錯、API 回的是字串而你當成物件——都會讓結果變成空的,而空的看起來就像「確實沒有」。

對策只有一個,而且很便宜:

拿一個確定存在的東西當試紙。 它若也回「沒有」,壞的是查法,不是東西。

05 §5 記了一個實際發生過的版本:查詢回的是字串,而程式照物件的形式寫,於是拋例外、集合停在空的,十一個型別全部印「沒有」——包含一個一定存在的。如果當時查詢裡放了那個一定存在的型別當對照,這個錯會在第一分鐘被抓到。

5. 排查的順序

順序本身就有價值,因為它決定了在錯誤方向上花掉多少時間。

  1. 先確認訊號是真的。 對照 §2,看手上拿來判斷的東西在不在左欄。在左欄的話,先換成右欄的訊號再說。
  2. 正對照。 新的訊號如果是列舉查詢,先用試紙確認查法是通的(§4)。
  3. 把 log 調到看得見那一層。 只針對相關 channel(§3)。
  4. 單變數。 一次只改一個東西。03 §7 量設定優先序用的是同一個方法。
  5. 極端值。 要證明某個設定真的生效,設一個大到行為必然改變的值。看得出差異才算生效。

第 1 步最容易被跳過,因為手上通常已經有一個「看起來很像證據」的東西了。跳過它的代價是後面每一步都建立在一個假前提上。

6. 待驗清單

# 待驗的斷言 怎麼驗 什麼算通過
1 啟動時 stdout 前幾行有 log 路徑(§3) 起一次應用,看前 20 行 找得到一個存在的檔案路徑
2 /log/file 執行期讀得到(§3) 用 --exec 跑腳本讀該設定 讀到的路徑與第 1 條一致
3 channel 萬用字元有效(§3) 把某一組 channel 設成 verbose、其餘 warn log 裡只有那一組變多
4 disable 真的關掉(§3) 把一個會固定輸出的 channel 設成 disable 該 channel 的訊息消失
5 §2 右欄各條在純 Kit 環境成立 逐條照各篇的待驗清單做 各篇的通過條件

第 5 條是這一篇對其餘七篇的依賴:這張對照表的價值建立在右欄那些訊號真的可用。 目前它們有的來自官方機制、有的來自姊妹 repo 在 Isaac Sim 上的實測,都還沒有在純 Kit 環境驗過。拿到環境後,這裡是最該先跑一輪的地方。
