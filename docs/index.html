Omniverse Kit 實戰筆記:框架這一層

大部分 Omniverse 的教學從應用開始講——開 Isaac Sim、開 USD Composer,點選單、拖物件。但那些應用共用的底座是同一套東西:extension 系統、carb settings、USD stage 與 Fabric、Hydra/RTX、OmniGraph、omni.ui。應用層查不到答案的問題,答案通常在這一層。

這裡整理的是 Kit SDK 本身的機制與踩坑,每篇從「要解決什麼根本問題」出發,並且標明哪些是官方機制、哪些是實測結論、哪些還只是推測。

三個入口

共通:機制與方法論 · 10 篇 不綁 Kit 版本的機制與方法。Kit 的多數概念——extension 相依樹、設定樹的優先序、stage 與 Fabric 的分工——跨版本是同一套,所以不按版本分。

Kit 107 · 0 篇 只在 107 系列成立的內容。Isaac Sim 5.0 / 5.1 底下就是這一版。

Kit 110 · 1 篇 只在 110 系列成立的內容。Isaac Sim 6.0 / 6.0.1 底下是這一版。

版本差異速查 跨版本排查最花時間的不是「哪裡不一樣」,是「這個症狀該不該歸給版本」。每一列都標出處與證據等級。

怎麼開始

你的處境 從這裡進

在 Isaac Sim 裡遇到問題,不確定該查誰的文件 01 §5 症狀該往哪一層找
手上有一套 Isaac Sim,想知道底下是哪一版 Kit 01 §4 版本對應
同一份程式碼在開發機能跑、換一台就說找不到 extension 02 §4 版本從哪裡拿
啟用了 extension,該有的東西卻不存在 02 §7 「啟用回傳成功」不是「它活著」
改一個檔案就整個應用停頓一下 02 §6 熱重載
設定寫了沒生效,或不確定誰蓋過誰 03 §3 先寫先贏 → 03 §7 自己量優先序
同一份程式碼在兩台機器行為不同 03 §6 /persistent 會活過重開
模擬在跑,讀出來的座標卻一直不變 04 §5 你正在讀哪一份
改完存檔,改動不見了 04 §3 資料只往一個方向流
物理在跑,但圖沒有輸出 05 §4 圖跟著誰求值
要用程式生成 OmniGraph,不想開介面拉 05 §2 節點型別與連線都是 USD 屬性
想知道 headless 能不能省下 GPU 預算 06 §2 兩個獨立的開關
串流連得上但畫面停在第一張 06 §5 串流的兩個結構性限制
算出來的畫面是黑的 07 §6 判別紀律:不要看畫面
東西設成不可見了,卻還是擋住路 07 §5 visibility 只影響算圖
手上的訊號到底能不能當證據 08 §2 假訊號與真訊號
不知道從哪裡開始查 08 §5 排查的順序
headless 想省記憶體,不確定該切哪一層 09 §3 UI 的存在是相依問題
開發機測過,搬到別台就不一樣 10 §3 版本解析的不確定性
要交付一個 Kit 應用,不知道該檢查什麼 10 §5 交付前的檢查
要從 107 升到 110,不知道會撞到什麼 11 官方列出的移除與棄用

這個 repo 的狀態

主題骨架已補滿,共 11 篇(共通 10 + Kit 110 一篇)。剩下的候選主題列在根 README 裡,每一群都標了還缺什麼。

本 repo 目前沒有自有的 Kit 環境,十一篇都是官方機制整理,篇首標明未實機驗證,並各自附了待驗清單(02 §8、03 §8、04 §6、05 §6、06 §7、07 §7、08 §6、09 §5、10 §6、11 §6)。拿到環境之後逐條升級。

機器人領域的內容在姊妹 repo isaac-sim-study(線上版)。兩邊的分工判準寫在 01 §6。
